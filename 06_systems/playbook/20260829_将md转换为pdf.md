# 20260829

## 将md转换为pdf

**注意**：不能在md中放太大的文件。

命令行输入指令

```
pandoc test.md -o test.pdf --pdf-engine=xelatex -V CJKmainfont="Noto Sans CJK SC" -f markdown-implicit_figures
```

> ### 为什么要用 `--pdf-engine=xelatex`？
> 
> 当使用 Pandoc 将 Markdown 转换为 PDF 时：
> 
> ```bash
> pandoc input.md -o output.pdf
> ```
> 
> Pandoc 默认通过 **LaTeX** 生成 PDF，而默认的 PDF engine 是 **`pdflatex`**。Pandoc 官方文档明确说明：
> 
> > “By default, pandoc will use LaTeX to create the PDF...”
> 
> 并且在 `--pdf-engine` 的说明中指出，未指定该选项时默认使用 `pdflatex`。
> 
> 对于包含中文的 Markdown，`pdflatex` 在 Unicode/CJK 字符和字体处理方面通常不如 `xelatex` 方便。Pandoc 官方针对 `CJKmainfont` 的说明明确指出：
> 
> > “`CJKmainfont` uses the `xecjk` package if `xelatex` is used...”
> 
> 也就是说，使用：
> 
> ```bash
> pandoc input.md -o output.pdf --pdf-engine=xelatex
> ```
> 
> 相当于明确告诉 Pandoc：
> 
> ```text
> Markdown
>    ↓
> Pandoc
>    ↓
> LaTeX
>    ↓
> XeLaTeX
>    ↓
> PDF
> ```
> 
> 这里的 `xelatex` 是一种 **LaTeX engine（LaTeX 排版引擎）**，负责把 Pandoc 生成的 LaTeX 文档真正排版成 PDF。
> 
> 对于中文，还可以配合 Pandoc 的：
> 
> ```text
> CJKmainfont
> ```
> 
> 指定中文字体；使用 `xelatex` 时，Pandoc 会通过 `xeCJK` 处理 CJK（中文、日文、韩文）文字。
> 
> 因此，`--pdf-engine=xelatex` **不是“开启中文模式”**，而是**将默认的 `pdflatex` 更换为 `xelatex`，从而使用更适合 Unicode/CJK 字体处理的 LaTeX 排版路径**。

> 20260831：
> ## 为什么要添加 `-f markdown-implicit_figures`？
> 
> ### 1. 问题根源
> 
> 当使用 Pandoc 将 Markdown 转换为 PDF 时，Pandoc 内部会先将 Markdown 转换为 LaTeX 代码，再调用 LaTeX 引擎编译成 PDF。
> 
> LaTeX 为了追求整体版面的美观，有一个 **“浮动体”（float）机制**。图片（`figure`）和表格（`table`）默认就是浮动体，LaTeX 引擎会**自动计算**把它们放在它认为最合适的位置（如页面顶部、底部或单独一页），**而不是严格遵循你在源文件中写的顺序**。这就是图片顺序错乱的根本原因。
> 
> ### 2. `implicit_figures` 扩展的作用
> 
> Pandoc 的 `implicit_figures` 扩展在 **`markdown` 格式下默认启用**。它的作用是：
> 
> > 当一张图片拥有**非空的替代文本（alt text）**，且该图片**单独出现在一个段落中**时，Pandoc 会自动将它转换为一个带标题的 **`figure` 环境**（即 LaTeX 浮动体）。
> 
> ```markdown
> <!-- 你的 Markdown -->
> ![这是图片标题](image.png)
> ```
> 
> ↓ Pandoc 转换后生成的 LaTeX 代码大致如下：
> 
> ```latex
> \begin{figure}
> \includegraphics{image.png}
> \caption{这是图片标题}
> \end{figure}
> ```
> 
> 这个 `figure` 环境在 LaTeX 中就是浮动体，LaTeX 会自主决定它的摆放位置，顺序因此被打乱。
> 
> ### 3. `-f markdown-implicit_figures` 做了什么
> 
> 命令 `pandoc -f markdown-implicit_figures ...` 的语法完全符合 Pandoc 官方手册的规定：
> 
> > **`-f FORMAT`**：指定输入格式。可以通过在格式名称后附加 `+EXTENSION` 或 `-EXTENSION` 来**单独启用或禁用扩展**。例如 `-f markdown-implicit_figures` 表示：**使用 Pandoc 的 Markdown 作为输入格式，但移除（禁用）`implicit_figures` 这个扩展**。
> 
> 禁用该扩展后的效果：
> - Pandoc **不再**自动将单独成段的图片包装成 `figure` 环境。
> - 图片变成普通的插图（`\includegraphics`），**不再是浮动体**。
> - LaTeX **不会**自动重新排列它，图片顺序因此得以保持。
> 
> ### 4. ⚠️ 代价：标题丢失
> 
> 禁用 `implicit_figures` 有一个直接副作用：**图片的标题（caption）会丢失**。因为标题是 `figure` 环境的一部分，既然不再生成 `figure` 环境，标题也就不会出现在 PDF 中。
> 
> ### 5. 适用场景总结
> 
> | 场景 | 推荐方案 |
> |------|----------|
> | 图片顺序必须正确，**标题可有可无** | 使用 `-f markdown-implicit_figures` |
> | 图片顺序必须正确，**标题也必须保留** | 使用 `-H` 插入 LaTeX 代码强制 `[H]` 定位（见下文） |
> | 只有少数几张图片需要保持顺序 | 在图片后面加 `\`（不换行空格），使其不再“单独成段” |
